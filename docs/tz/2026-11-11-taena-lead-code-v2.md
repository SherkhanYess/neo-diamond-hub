# ТЗ: код обращения v2 на сайте taena (taena.neodiamond.kz)

Для сессии, которая ведёт сайт-каталог taena (`~/neo-diamond-lenta`, ветка `lenta`).
Автор — сессия инфоцентра (`~/neo-diamond-hub`). Дата: 11.11.2026.

## Зачем

Код в сообщении WhatsApp больше не переносит менеджер руками. Его читает
инфоцентр: Salesbot amoCRM записывает первое сообщение клиента в поле сделки
«Код обращения», вебхук инфоцентра вырезает из текста код, оставляет в поле
только его и по нему ставит источник спроса и конвертер.

Поэтому код должен быть **машиночитаемым и однозначным**. Нужно, чтобы по нему
было видно:
- бренд;
- откуда человек пришёл на сайт: bio, сторис, пост или реклама;
- какое объявление, если пришёл из рекламы;
- тип обращения;
- страница, с которой нажали WhatsApp: лента, модель или гид.

Гид — та же витрина, просто другая вкладка. Отдельного конвертера у гида нет:
конвертер «Сайт», страница «гид».

## Как сейчас

`src/catalog/lib/leadCode.js`, `waMessage.js`, `components/model/whatsapp.jsx`:

| Что | Сейчас |
|---|---|
| Формат | `[<источник>-<тип>·<кампания>]`, например `[К-ПР·РК Помолвка_Таргет]`; без кампании `[П-ОБ]` |
| Источник | одна кириллическая буква: К — реклама (`utm_medium=performance`), Г — `utm_source=guide`, П — instagram + bio/stories/post (все три сливаются), С — всё остальное и прямой заход |
| Тип | ОБ, ПР, ПД, НМ, ИД (price, fitting, help, hint, custom) |
| Кампания | `utm_campaign` целиком, бывает длинной и с пробелами |
| Объявление | в код не попадает, хотя `{{ad.id}}` уже приходит в `utm_term` |
| Страница | не видна. С гида уходит тип `price` без модели, и такое сообщение не отличить от подвала сайта |
| Бренд | не виден |
| Метки | `sessionStorage` (`nd_utm`), живут один визит во вкладке. Вернулся завтра напрямую — код `С` |
| Намёк | ссылка-намёк несёт букву отправителя латиницей (`utm_source=K\|P\|G\|S`) |

## Как надо

### Формат

```
[T·<вход>[:<объявление>]-<тип>·<страница>]
```

- `T` — бренд taena. Всегда `T` на этом сайте; `N` зарезервировано за Neo Diamond.
- `·` — средняя точка U+00B7, как сейчас. Парсер принимает и обычную точку.
- `<вход>` — две латинские буквы, таблица ниже.
- `:<объявление>` — только если в метках есть номер объявления: 5 символов base36,
  алгоритм ниже.
- `<тип>` — как сейчас: ОБ, ПР, ПД, НМ, ИД.
- `<страница>` — одна латинская буква: `f` — лента (главная), `m` — страница модели,
  `g` — гид, `o` — остальное (подвал, страница намёка, поделиться).

Примеры:

| Ситуация | Код |
|---|---|
| Из bio, с ленты, «узнать стоимость» | `[T·ib-ОБ·f]` |
| Из сторис, со страницы гида | `[T·is-ОБ·g]` |
| Из рекламы, объявление 120246670349460187, примерка со страницы модели | `[T·ia:51l97-ПР·m]` |
| Прямой заход без меток, «помогите выбрать» в конце ленты | `[T·dd-ПД·f]` |
| Намёк от человека, который пришёл из рекламы | `[T·ia-НМ·m]` |

Длина — 12–19 символов вместо кампании целиком.

### Вход: из меток в две буквы

Проверять сверху вниз, первое совпадение побеждает:

| Условие по меткам | Вход | Значение |
|---|---|---|
| `utm_medium=hint` | из `utm_source` ссылки-намёка (там теперь две буквы входа отправителя); если пусто — `ht` | намёк |
| `utm_medium` = `performance` / `cpc` / `paid`, `utm_source` = instagram / facebook / meta | `ia` | реклама Meta |
| `utm_medium` = `performance` / `cpc` / `paid`, `utm_source=tiktok` | `ta` | реклама TikTok |
| `utm_source=instagram`, `utm_medium=bio` | `ib` | шапка профиля |
| `utm_source=instagram`, `utm_medium=stories` | `is` | сторис |
| `utm_source=instagram`, `utm_medium` = `post` / `reels` | `ip` | пост, reels |
| `utm_source=tiktok` (не реклама) | `tb` | профиль TikTok |
| `utm_source=2gis` | `gs` | ссылка на сайт из карточки 2ГИС |
| `utm_source=whatsapp`, `utm_medium=manager` | `wm` | менеджер прислал ссылку в чате |
| `utm_term=share` | `sh` | поделились ссылкой |
| меток нет | `dd` | прямой заход |
| метки есть, но не подошли | `xx` | другое (внешний гайд и т. п.) |

Сейчас в ссылке-намёке `utm_source=K|P|G|S`. Теперь там две буквы входа
отправителя (`utm_source=ia`). Старые ссылки-намёки с одной буквой пусть
продолжают работать: K → `ia`, P → `ip`, G → `dd`, S → `dd`.

### Номер объявления: 5 символов

Берём из `utm_term`, а если там не число — из `utm_content`. Номер — только из
цифр, не короче 6 знаков:

```js
const short = (BigInt(adId) % 60466176n).toString(36).padStart(5, '0') // 36^5
```

`120246670349460187` → `51l97`. Инфоцентр восстановит полный номер по списку
объявлений из Meta. Совпадение двух объявлений почти невозможно: 60 млн значений
на сотни объявлений.

### Метки живут дольше визита

Сейчас `nd_utm` лежит в `sessionStorage`. Надо:
- новые непустые метки входа перезаписывают старые, как сейчас;
- дополнительно класть их в `localStorage` (`nd_utm_last`) вместе с датой и брать
  оттуда, если в этом визите меток нет, а прошло не больше **30 дней**;
- прямой заход без меток не стирает сохранённые метки.

Так человек из рекламы, который вернулся через три дня по закладке, останется
рекламным.

### Где что меняется

- `leadCode.js`:
  - новая `leadCode(type, utm, page)` по формату выше;
  - `sourceCode` превращается в `entryCode` (две буквы) по таблице;
  - `sourceLatin` для намёка отдаёт те же две буквы.
  
  Тесты обязательны: каждая строка таблицы входов и все примеры выше.
- `waMessage.js`: передаёт страницу в `leadCode`. Тексты сообщений не меняются.
- `whatsapp.jsx` (`useWhatsApp`): `open(type, ctx, props)` получает страницу.
  - Лента (`FeedScreen`) — `f`.
  - Модель (`DetailScreen`) — `m`.
  - Гид (`GuideScreen`, блоки гида) — `g`.
  - Подвал (`SiteFooter`) и прочее — `o`.
  
  В `track(EVENTS.WA_CLICK …)` поле `code` — новый код.
- `DetailScreen.jsx`: ссылка-намёк — `utm_source=<вход отправителя>`. Код на странице
  намёка показывается в новом формате.
- `catalog-main.jsx` (`captureUtm`): хранение на 30 дней, как описано выше.
- Админка, раздел «Ссылки» (`src/studio/utm.js`): пресеты не меняются. Добавить
  строку-подсказку, какой код даст каждый пресет (`ib`, `is`, `ip`, `wm`).
  `ADS_URL_PARAMS` не трогать: `{{ad.id}}` в `utm_term` уже есть.

### Не трогать

- Конструктор (`src/configurator`) и con.neodiamond.kz.
- Каталог Neo Diamond (neodiamond.kz/catalog), таплинк и номер обращения
  (`#A7K2` из черновика `0010_site_events.sql`) — отдельно, позже.
- Тексты сообщений и логику выбора шоурума.

## Переходный период

Инфоцентр уже понимает и старый формат: `[К-ПР·…]` → вход `ia`, `[П-ОБ]` →
Instagram (без деления на bio, сторис и пост), `[С-…]` и `[Г-…]` → без источника.
Поэтому выкатывать можно в любой момент, и старые сообщения в чатах не ломаются.

## Приёмка

1. `npm test` зелёный. Есть тесты `leadCode` на все строки таблицы входов, номер
   объявления и примеры.
2. Открыть на телефоне (390 px) и нажать WhatsApp:
   - `…/?utm_source=instagram&utm_medium=stories` → в сообщении `[T·is-…·f]`;
   - `…/?utm_source=instagram&utm_medium=performance&utm_term=120246670349460187`,
     страница модели → `[T·ia:51l97-ПР·m]` или `[T·ia:51l97-ОБ·m]`;
   - то же, но через гид → `…·g]`.
3. Закрыть вкладку, открыть сайт без меток, нажать WhatsApp → вход прежний,
   а не `dd`.
4. Отправить одно реальное сообщение в WhatsApp Алматы. Через несколько секунд
   в поле сделки «Код обращения» останется только код. Проверку делает
   инфоцентр.
5. Сообщить в сессию инфоцентра: «код v2 выкачен», дата деплоя.
