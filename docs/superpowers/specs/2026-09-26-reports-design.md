# Фаза 3: Маркетинг + Продажи (факт) — дизайн

Дата: 2026-09-26 · Проект: neo-diamond-hub

## Контекст и границы

Две страницы отчётов на одной модели данных: рядом с утверждённым планом
(снимок `computed` из фазы 2) встаёт факт из сделок amoCRM.

**В фазе:** модель сделок (`deals` + `deal_stage_events`), движок агрегации
факта (воронка, конверсии, выручка/заказы по задаче и источнику, медиана цикла),
правило «н/д», страницы **Продажи** (воронка) и **Маркетинг** (Матрица план/факт
+ Воронка), общая панель фильтров. План берётся из снимка утверждённого плана.

**Интеграционная стена:** живой sync с amoCRM (API + вебхуки) — отдельный шаг,
нужны ключи. Здесь `deals` наполняется реалистичным сидом; структура полей
совпадает с тем, что положит sync. Стоимость этапа и фактические CAC/ROAS
требуют рекламного расхода (фаза 5 / ручной ввод) — до него показываются «н/д».

## Модель данных (0007_deals.sql)

- **deals** — `id`, `crm_id` (text), `branch_id`, `client_task_id` (null до
  квалификации), `lead_source_id` (null; ставится на обращении),
  `demand_source_id` (null до «Встреча состоялась» — первое касание),
  `manager_id`, `created_at` (дата обращения), `current_stage_id`,
  `revenue` (полная сумма сделки, null до продажи), `sale_at` (дата продажи/
  предоплаты, null), `receive_date` (срок получения), `is_ignored` (bool),
  `lost_reason` (text), `ad_id` (text, для фазы 5).
- **deal_stage_events** — `deal_id`, `stage_id`, `entered_at`. Строка на каждый
  вход сделки в этап; из них считаются число на этапе и цикл сделки.
- RLS: чтение обеих таблиц — `view_reports` (или edit/approve/settings).

## Движок факта (`src/lib/reports/fact.js`, чистые функции, тесты)

Когорта — сделки с обращением (created_at) в выбранном периоде и филиале.

- **Воронка (факт):** число на этапе = сколько сделок когорты достигли этапа
  (есть событие входа). Конверсия факт = число_{i+1} ÷ число_i.
- **Правило «н/д»:** при фильтре по клиентской задаче этапы до «Квалифицирован»
  → null (н/д). При фильтре по источнику спроса этапы до «Встреча состоялась»
  → null. Конверсии считаются только между доступными этапами.
- **Выручка/заказы факт:** сумма revenue и число сделок с продажей (sale_at) в
  когорте, по клиентской задаче (поле) и источнику спроса (первое касание).
- **Средний чек факт** = выручка ÷ заказы.
- **CAC/стоимость этапа факт:** требуют расхода → null (н/д) до фазы расхода.
- **ROAS факт:** требует расхода → null.
- **Цикл сделки:** медиана (sale_at − created_at) в днях по когорте с продажей,
  плюс число сделок, по которым посчитано. Только факт.

## Интерфейс

Общая панель фильтров (в шапке рабочей области): период (месяц), город, филиал,
клиентская задача, источник спроса, источник лида, менеджер. Сохраняется в URL.

- **Продажи** — вид «Воронка»: строки-этапы, столбцы План / Факт / % / Конверсия
  (план·факт) / Стоимость этапа (план·факт, «н/д» без расхода). Итоги план/факт:
  выручка, средний чек, заказы. Цикл сделки (медиана + число сделок).
- **Маркетинг** — две вкладки:
  - **Матрица план/факт** (по умолчанию): строки задача × источник, столбцы
    (план/факт/%): выручка, заказы, средний чек; CAC/ROAS — «н/д» без расхода.
    Цвет ячейки по порогам выполнения (из display_settings). Клик по строке →
    Воронка с этими фильтрами.
  - **Воронка**: как на «Продажах», но с разрезом маркетинга.
- Если план не утверждён — страница показывает только факт и кнопку «Перейти к
  планированию».
- Правило «н/д» видно на экране; подпись про атрибуцию источников «по дошедшим
  до встречи».

## Тесты

Движок факта: воронка по когорте, конверсии, н/д при фильтрах, выручка/заказы по
задаче и источнику, медиана цикла (нечётное/чётное число), пустая когорта.

## Критерии приёмки

- [ ] Факт по этапам воронки совпадает с сидом сделок за период и филиал.
- [ ] Фильтр по задаче → этапы до «Квалифицирован» показывают «н/д».
- [ ] Фильтр по источнику спроса → этапы до «Встреча состоялась» «н/д».
- [ ] План рядом с фактом из утверждённого снимка; без плана — только факт.
- [ ] Цикл сделки — медиана по когорте обращений, нигде не в плане.
- [ ] Клик по строке матрицы открывает воронку с фильтрами.
