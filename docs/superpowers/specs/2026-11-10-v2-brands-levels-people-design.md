Дата: 2026-11-10 · Основание: `tz-info-center-v2.md` (Шерхан, 10.11.2026)

## Порядок работ (решение)

Сначала структура, потом живые интеграции. Структура задаёт поля, которые
amoCRM/Meta обязаны заполнять (бренд, UTM → источник/конвертер, лид-менеджер /
консультант / аккаунт-менеджер, повторная продажа). Пустые экраны на время
разработки закрываются демо-сидом новой формы (`crm_id like 'v2demo-%'`).

| --- | --- | --- |

## Модель данных

**Бренд.** `brands` (Neo Diamond `2000…0001`, taena `2000…0002`). `brand_id`
(NOT NULL, default Neo Diamond — так всё существующее автоматически стало Neo
Diamond) на: `client_tasks`, `demand_sources`, `ad_entities`, `deals`,
`converters`, `utm_rules`, `spend_entries`. На `plans` — nullable: у плана
коммерции бренд обязателен, план отдела продаж общий (brand_id null).

Общее (без бренда): пользователи, роли, города, филиалы, воронка, отдел продаж.

**Конвертер** принадлежит источнику спроса (`converters.demand_source_id`).
`entry_source` говорит, откуда берётся «вход» воронки: `taplink`
(taplink_events), `site` (site_events), `ads` (клики объявлений), `none`.

**UTM → конвертер.** `utm_rules` (шаблоны `*` по source/medium/campaign/content,
`priority` — меньше раньше). Единственный источник истины — SQL-функция
`resolve_utm()`; триггер на `deals` при вставке/смене UTM ставит
`converter_id`, а из него `demand_source_id`. Числовой `utm_term`/`utm_content`
становится `ad_id`. Настройки тестируют правило через RPC той же функции.

**Сделка.** + `brand_id`, `utm_*`, `converter_id`, `lead_manager_id`,
`consultant_id`, `account_manager_id`, `is_repeat`, `first_response_minutes`.
Старый `manager_id` сохранён и скопирован в `consultant_id` (история).

**Расход.** `ad_daily_stats` (по дням на объявление — так отдаёт Meta Insights)
и `spend_entries` (ручной расход для нерекламных источников). Вложения источника
за период = сумма обоих.

## Правила расчёта

- Одна база факта везде: **когорта обращений периода** (сделки с `created_at` в
  периоде). Поэтому итоги Коммерции = сумме Маркетинга = Отделу продаж за тот же
  период и бренд — по построению, один движок.
- Источник спроса теперь известен с «Обращения» (UTM). Правило «н/д до встречи»
  для источника снято; для клиентской задачи («н/д до квалификации») осталось.
- ROAS = выручка когорты ÷ вложения периода; CAC = вложения ÷ продажи.
- Двойная атрибуция: лид-менеджеру засчитываются этапы до «Встреча
  состоялась», консультанту — продажа (не повторная), аккаунт-менеджеру —
  повторная продажа.

## Миграция без потерь

Бэкап всех таблиц в JSON перед каждой миграцией (`~/neo-diamond-hub-backups/`).
Только аддитивные изменения и backfill; ни одна колонка не удаляется. Старые
планы (сентябрь, октябрь) и сделки открываются и относятся к Neo Diamond.
