# Финансы, этап 2: финмодель — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** живая финмодель по месяцам во вкладке «Финансы»: вводим выручку, чек, % фондов, нормы на продажу, постоянные суммы и оклады — остальное считается; рядом факт прошлого месяца на продажу и расхождение с «Планированием».

**Architecture:** таблица `fin_models` (месяц → вводные в jsonb); чистые движки `src/lib/finance/model.js` (расчёт строк модели) и `sales.js` (продажи Adesk: заказы по акту/названию + склейка продаж из наличия + сверка с amoCRM); оклады модели месяца идут в разнесение ДДС; экран `ModelTable.jsx`.

**Tech Stack:** Supabase, React 19, Vitest.

Спека: `docs/superpowers/specs/2026-11-19-finance-design.md` (раздел «Финмодель»).

## Решения по расчёту (из ТЗ и скрина модели)

- Вход фонда — одно из: `pct` (% от выручки для переменных, % от маржи для управления), `amount` (₸ в месяц), `per_sale` (₸ на продажу, только фонды `per_sale`). Второе значение выводится: сумма = % × база, % = сумма ÷ база, на продажу = сумма ÷ продажи.
  Так поддержаны оба вида строк скрина: «47% · 469 300 ₸» и жёлтые суммы «Фонд развития 3 500 000».
- Продажи (план) = выручка ÷ средний чек. Маржа = выручка − прямые переменные.
- Постоянные фонды со строками (аренда, прочие, оклады) = сумма строк; % от выручки выводится.
- Оклады — строки фонда «Фонд оплаты труда»; оклад человека (fin_people) месяца = строка модели. ДДС этого месяца делит выплаты по окладу модели.
- Благотворительность — внутри фонда дивидендов: `charity_pct` — % от дивидендов (на скрине 525 000 = 2,5 % × 21 000 000), фонд = дивиденды + благотворительность.
- Остаток = маржа − управление − постоянные.
- Новый месяц — копия последней модели до него; старые месяцы не меняются. Базовая модель — скрин 1 ТЗ (на ретро-данных сентября), месяц 2026-09.

## Продажи Adesk (`sales.js`)

- Заказ — сделка `type=deal` с 4 цифрами. Месяц продажи — `act_date`; нет акта — месяц из названия («8935 ноябрь») с годом из даты создания; иначе — месяц создания. Исключённые проекты (статуэтка) не считаются. Выручка — `deal_amount`.
- Из наличия — поступления проектов `product_deal` месяца, склеенные: тот же проект, общие значимые слова описания (без имён продавцов: «голд», «жанар», «жанара»), разрыв ≤ 7 дней → одна продажа. Возврат на всю сумму продажи отменяет её.
- Сверка с amoCRM: продажа из наличия подтверждена, если есть закрытая сделка amoCRM с выручкой ±5 % и датой продажи ±10 дней.
