# Neo Diamond — Информационный центр

Единая платформа планирования и отчётности Neo Diamond. Этот репозиторий —
**фаза 1 (Фундамент)**: авторизация, роли и права, справочники и модуль
«Настройки». Отчётные модули (Планирование, Маркетинг, Продажи, Журнал решений,
Performance) добавляются следующими фазами.

Стек: React 19 + Vite + Supabase (Postgres + Auth + RLS) + Netlify.

## Локальный запуск

1. Создать **новый** проект на supabase.com.
2. Применить миграции из `supabase/migrations/` по порядку в SQL Editor:
   `0001_auth_roles.sql`, `0002_references.sql`, `0003_settings_audit.sql`,
   `0004_rls.sql`, `0005_seed.sql`.
3. Завести первого владельца (на старте некому его пригласить):
   - В Supabase → Authentication → Users → Add user: создать пользователя с email
     и паролем (подтвердить email вручную галочкой «Auto Confirm»).
   - Скопировать его `id` и связать с ролью «Владелец»:
     ```sql
     insert into profiles (id, full_name, role_id)
     values (
       '<UUID пользователя из Auth>',
       'Шерхан',
       '10000000-0000-0000-0000-000000000001'  -- роль «Владелец» из сида
     );
     ```
4. Скопировать `.env.example` в `.env` и вписать `VITE_SUPABASE_URL` и
   `VITE_SUPABASE_ANON_KEY` (Project Settings → API).
5. `npm install`
6. `npm run dev`

## Тесты

`npm run test`

## Деплой

Подключить репозиторий к Netlify — конфигурация в `netlify.toml`. Добавить
`VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в Site settings → Environment
variables.

## Что внутри (фаза 1)

- **Вход** по email + паролю (Supabase Auth). Без сессии — редирект на `/login`.
- **Роли и права**: набор прав (`caps`) на роль, область по филиалам. Пункты меню
  без права не показываются; запись данных защищена RLS.
- **Справочники**: города, филиалы, клиентские задачи (со свёрткой), источники
  спроса и лида, этапы воронки (с флагами «квалификация»/«продажа»). Правило
  «архив вместо удаления» для используемых элементов.
- **Настройки → Отображение**: пороги цвета плана, валюта, начало недели.
- **Настройки → Журнал изменений**: кто/что/когда менял.
- Всё оформление — из токенов брендбука (`src/styles/tokens.css`).

Документы проектирования: `docs/superpowers/specs/` и `docs/superpowers/plans/`.
